## Проверяемая конструкция

Пусть p(i,j) — распределение соседних положительных прослушиваний с lag (0,30 min], построенное только из прошлого. Global noise — переставленные target endpoints всей таблицы. Context-preserving noise — target endpoints, переставленные отдельно внутри user–day. Второй фон сохраняет маргинальные source/target counts каждого strata и их дневную популярность, разрушая конкретное соответствие i→j.

Balanced discriminator имеет logit `dot(a_i,b_j)/sqrt(64)`. При неограниченной функции и идеальной оптимизации оптимальный logit равен `log(p(i,j)/q(i,j))`. В нашей low-rank модели это только мотивация, не гарантия точной оценки. User/day не подаются в encoder: q — **маргинальная смесь условных фонов**, а не обещание оценить персональный conditional probability. Пользовательский профиль получается из source embeddings его прошлых событий.

Основная абляция совпадает по архитектуре, embedding dimension, epochs, batch order, инициализации, feature count и HPO budget; меняется фон. Это позволяет исследовать содержательный вопрос: полезнее ли отделять переходы от user/day вкусов или такое вычитание уничтожает важную для рекомендаций информацию?

[Математический разбор](DENSITY_RATIO.md) выводит ожидаемые counts после перестановки и оптимум balanced discriminator. В таблицах используется краткое имя NCE, но реализован density-ratio critic без отдельного log-q correction, а не полная репликация density estimator из статьи 2010 года.

Нулевой/отрицательный результат возможен: данные содержат logging policy; композиция дня сама по себе полезна; static pair encoder не описывает более длинные зависимости; равные пятисекундные timestamps неоднозначны; next-day задача отличается от next-item. При ties adjacency задаётся стабильным item-ID порядком, но edges с delta=0 исключены. Это ограничивает буквальную интерпретацию «порядка».

Фиксируем конкретный самостоятельный метод и его matched comparison, **не заявляем доказанный мировой приоритет**. Ни обзор, ни отсутствие найденной идентичной формулы не доказывают такой приоритет. [Протокол](RESEARCH_V3_PROTOCOL.md) фиксирует основной вопрос до test; [отчёт](../reports/v3/REPORT.md) отделяет проверенные результаты от возможных объяснений.
