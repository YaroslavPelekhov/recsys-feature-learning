# Какой сигнал учит условный фон

Это вывод для нашего экспериментального дизайна, а не утверждение о новом общем принципе NCE. Он объясняет, почему хорошая классификация real/noise не обязана давать хорошие рекомендации.

## Два фоновых распределения

В страте z = (user, day bucket) есть n_z наблюдаемых переходов. Обозначим через a_zi число source endpoints объекта i, через b_zj — число target endpoints объекта j. Источники остаются на месте, target endpoints равновероятно переставляются.

Для каждой из a_zi позиций вероятность получить j равна b_zj/n_z. Поэтому:

`E[C_null(i,j)] = sum_z a_zi * b_zj / n_z`.

Это следует из линейности ожидания; независимость переставленных позиций не нужна. Страта с одним переходом воспроизводит его как noise. Это корректное поведение null, не основание удалять такой пример. Каждая перестановка в точности сохраняет source/target margins внутри strata. Числа относятся к counts до shrinkage и pruning графового оператора.

Если p_z(i,j) — наблюдаемое распределение пары внутри z и pi_z=n_z/N, то:

`p(i,j) = sum_z pi_z * p_z(i,j)`;

`q_global(i,j) = p_source(i) * p_target(j)`;

`q_context(i,j) = sum_z pi_z * p_source(i|z) * p_target(j|z)`.

При глобальной перестановке q_global получается в ожидании по permutation. При условной — q_context. Фактические finite-sample tables имеют дополнительный перестановочный шум.

Обе конструкции точно сохраняют глобальные endpoint margins. Поэтому одна лишь unary item popularity не различает real/noise классы в этом эксперименте. Различие относится к joint ассоциациям и дополнительному сохранению user–day структуры, а не к наличию/отсутствию любой коррекции популярности.

## Оптимум дискриминатора

Для одинаковых вероятностей двух классов используем:

`L(f) = 0.5 E_p log(1 + exp(-f)) + 0.5 E_q log(1 + exp(f))`.

Поточечная производная:

`dL/df = [-p + q*exp(f)] / [2*(1+exp(f))]`.

При p,q>0 стационарная точка имеет `f* = log(p/q)`. При нулевой массе одного класса оптимум может быть бесконечным; low-rank parameterization и регуляризация ограничивают реальные logits.

У нас `f_theta(i,j) = dot(a_i,b_j)/sqrt(64)`. Это ограниченный rank-64 critic, а не unrestricted optimum. Мы **не** вычитаем отдельно известный log q из logit, чтобы восстанавливать нормированную data density. Поэтому точный термин — noise-discrimination / density-ratio embedding; название «NCE» в таблицах означает NCE-style обучение, не гарантию consistent density estimation исходной статьи Gutmann–Hyvärinen.

User/day не входят в neural input. Модель различает marginal p и mixture q_context. Она не оценивает `p(next_item | user, day, current_item)` и не получает causal effect из одной перестановки.

## Что удаляется и что остаётся

Если внутри каждой strata source и target условно независимы, то p=q_context и ожидаемый contrast равен нулю. При этом p может сильно отличаться от q_global: пользовательский музыкальный вкус создаёт сильные маргинальные ассоциации даже без зависимости между соседними треками.

Следовательно, conditional critic может удалить полезную для рекомендаций часть сигнала. Его положительный score означает избыток относительно данного null, а не большую вероятность следующего прослушивания. Ранжирование по одному f без фоновой компоненты q не восстанавливает p. Пользовательская агрегация source embeddings также не превращает density ratio в calibrated probability.

Есть и отдельная проблема поддержки: если p(i,j)=q_context(i,j)=0, BCE для этой пары отсутствует. Значение параметрического score может определяться sharing/regularizer, но данные этой пары его не идентифицируют. При score около нуля такая ненаблюдаемая пара способна оказаться выше наблюдаемых пар с отрицательным log-ratio. Смесь с положительной global-компонентой убирает noise holes на поддержке source/target marginals: `q_mix >= lambda*q_global`, lambda>0. [Вторичное дополнение](V3_SUPPORT_AMENDMENT.md) фиксирует проверку этой идеи до открытия test.

Отсюда две проверки: standalone diagnostic показывает, какие предпочтения потеряны; matched hybrids с ручным prior проверяют, добавляет ли остаточный сигнал качество сверх counts/recency/artist preference. Оба исхода содержательны. Низкий standalone NDCG не доказывает бесполезность признака, а низкий training loss не доказывает его полезность.

## Вычислительная форма

Для sparse профиля x_u score кандидатов равен `(x_u A) B^T / sqrt(64)`: пользовательский вектор вычисляется один раз и переиспользуется. Параметры — O(I*d), training work приблизительно O(epochs*E*d), без плотной I×I матрицы. Sparse optimizer требует moment states; сложность coalescing и построения permutation также учитывается в реализации.

При фиксированных history budget L и candidate budget K скоринг требует O((L+K)*d) на пользователя. Текущий exact neural retrieval всё ещё требует O(U*I*d) и материализует score blocks. Это практическое ограничение кода, а не промышленный ANN-индекс.

Здесь z — сутки относительно анонимизированного начала, не установленный календарный день/локальный часовой пояс пользователя. Null не устраняет session identity, logging policy, скрытые причины или неоднозначность пятисекундных ties. Поэтому вывод о predictive association не является выводом о причинности.

## Почему усреднение embeddings тоже меняет задачу

Для нормированного профиля с весами w_ui, суммирующимися в единицу, билинейность даёт:

`score_u(j) = sum_i w_ui * f(i,j)`.

Даже если бы unrestricted global critic был найден точно, на положительной поддержке:

`f_global(i,j) = log p(j|i) - log p_target(j)`;

`score_u(j) = log [product_i p(j|i)^w_ui / p_target(j)]`.

Это геометрическое объединение условных вероятностей с делением на target marginal. Оно отличается от арифметической смеси `sum_i w_ui*p(j|i)` и от вероятности прослушать трек на следующих сутках. Для context critic знаменатель зависит также от source и структуры strata; простого универсального добавления log popularity уже недостаточно. Реальный rank-64 encoder, неполная поддержка и регуляризация дополнительно отдаляют scores от этих идеальных формул.

Поэтому ни высокий training-pair AUC, ни удачный low-rank fit не обосновывают использование среднего embedding как calibrated next-day predictor. В нашем дизайне manual prior сохраняет counts/recency/artist preference, а primary hybrids проверяют только добавочную ценность critic scores. Отдельная fusion со смесью noise — вторичная проверка, не результат указанной формулы и не доказанная коррекция вероятностей.
