# Финальная проверка: восстановление массы и агрегация истории

Протокол записан 18 октября 2026 до выбора новых настроек и до построения целей новой user-когорты. Test v1/v2/v3 открыт; его результаты не используются для нового выбора. Мотивация следует из опубликованного отрицательного результата v3 и математического разбора density-ratio scores.

## Вопрос и вклад

Хорошее различение реальных и шумовых переходов не гарантирует хорошее ранжирование следующего дня. Для global noise оптимальный неограниченный critic имеет вид f(i,j)=log p(j|i)-log q(j). Усреднение embeddings геометрически объединяет отношения вероятностей. Проверяем отдельно два изменения: возвращение известного target marginal q(j) и арифметическую смесь условных распределений переходов.

Это контролируемая конструкция и её экспериментальная проверка, а не заявление о новом общем принципе NCE, Bayes correction или opinion pooling. Параметры encoder, candidate retrieval и baseline наследуются из v3. Представления обучаются на прошлом новой когорты с нуля, без supervised test labels.

## Четыре фиксированных варианта

Для каждого пользователя C_u — общий пул кандидатов v3. История — последние 100 положительных прослушиваний, half-life **24 часа** для всех вариантов, без поиска этого окна. Нейросеть — global-noise encoder v3, 64 dimensions, 15 epochs, seeds 17/42/73. q(j) — частота target endpoints в тех же прошлых 30-дневных transition pairs.

В основном факторном сравнении используются одинаковые source/target role masks: source с хотя бы одним обучающим source endpoint, target с положительной q. После маскирования source-веса нормируются. Для источника i и b∈{0,1}: l_ij=f(i,j)+b log q(j), r_i(j)=softmax_{j∈C_u}(l_ij).

- G0: сумма w_i log r_i(j), фон не восстановлен.
- G1: сумма w_i log r_i(j), добавлен log q.
- A0: log суммы w_i r_i(j), фон не восстановлен.
- A1: log суммы w_i r_i(j), добавлен log q.

G0/G1 — geometric pooling, A0/A1 — arithmetic pooling. Численная нижняя граница probability 1e-12 одинакова; недоступный target имеет score log(1e-12). Если нет валидных источников, все варианты используют один q-prior на доступных candidates; если и q не имеет массы, scores нулевые. Никакой будущей информации в q или masks нет. Отдельный legacy-контроль — исходный global_h24 без новых role masks. Это отделяет эффект поддержки от основных двух факторов.

Нормировка выполнена по извлечённому C_u. Это смесь candidate-conditioned экспертов с фиксированными историческими весами, **не** доказанное восстановление полной p(next item|history) и не обязательно условная версия generative mixture по всему каталогу.

## Development и вторичные fusion-варианты

Development — существующая когорта v3, seed2028, только старые train/search. Основная факторная конструкция полностью задана выше и не подбирается по метрикам. На search294 для каждого из четырёх вариантов выбирается alpha∈{0,.05,.1,.25,.5} в query-z-normalized manual + alpha*query-z-normalized reconstructed score: всего20 trials, без нового поиска baseline/encoder. Manual search-модель из v3_support обучена только на train286/288/290/292. Alpha0 возвращает точные manual scores. Лучший fusion по search записывается отдельно; все варианты и проигрыши публикуются.

## Внешняя когорта и временная схема

Из реально присутствующих в pinned listens пользователей исключаются все1000 UID v3. До development-поиска равномерно резервируются1000 новых UID с seed **424242**; сохраняются все их исходные строки listens. Manifest и его SHA фиксируются. Никакого отбора по будущей активности. Когорты не пересекаются по UID, но могут иметь общие item IDs и относятся к одному сервису/периоду. Это **перенос на новую user-когорту**, не временная репликация или независимый сервис.

Временные cutoffs, labels и gap совпадают с v3: train286/288/290/292/294/296 для финального manual, test298/299, горизонт сутки, history t<day*86400-1800, positive played_ratio_pct>=50, повторы разрешены. Внешний manual переобучается на новой когорте с уже фиксированными depth7/550trees/lr.05/L2=5, seeds17/42/73. Гиперпараметры по новой когорте не выбираются. Для обучения нужны её исторические labels до297; внешние targets298/299 закрыты до сохранения **всех** прогнозов.

Исходный общий RRF-пул v3 до300 кандидатов строится отдельно по прошлому новой когорты. Все методы видят один набор; reconstruction не номинирует новые items. Исходные global/conditional encoders, необходимые общему retrieval, сохраняются. Второй test день обновляет unsupervised историю по доступным событиям; supervised manual не дообучается на первом test дне. Все forecasts обоих дней сохраняются прежде, чем строятся target sets.

## Оценка и ограничения

**Единственное основное сравнение: A1 − G0 по end-to-end NDCG@10.** Оно проверяет совместную реконструкцию; факторные эффекты и взаимодействие — вторичные описательные оценки. G1−G0 и A1−A0 характеризуют восстановление фона, A0−G0 и A1−G1 — агрегацию. Сравнения с manual, legacy, fusion, repeat/popularity/userKNN — вторичные. При успехе primary нельзя утверждать победу над бустингом без отдельного соответствующего свидетельства.

Mean seeds внутри user–day, затем mean дней внутри пользователя, затем user macro. Парный user-cluster bootstrap3000 resamples seed424242; все цели, включая cold/unretrieved, остаются в знаменателях. Дополнительно Recall/MAP, candidate recall, oracle, repeat/novel и exposure. Вторичные интервалы без multiplicity correction. Три seeds не заменяют другие user samples и периоды. Нулевая разность тождественных alpha0 fusion не доказывает эквивалентность разных моделей.

До внешней проверки сохраняются frozen recipe, code/input hashes, полная search-траектория. После неё выполняются replay и future-content invariance. Не исправляем числа задним числом, не выбираем новый alpha или вариант по внешним метрикам. Raw/model/cache — runs/v4 и data, компактные доказательства — reports/v4. Измеряются завершённые prepare/fit/score stages; параллельные durations не суммируются как изолированный elapsed benchmark.
